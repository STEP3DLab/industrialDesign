# СДО лаборатории промышленного дизайна и инжиниринга

**СКБ Технопарка РГСУ · «Цифровая метрология» · 72 академических часа**

Серверный проект Moodle LMS 4.5.15 LTS (исходный commit `215f44380bdc3ccf852a3a22e34f8423ff64033a`), PHP 8.3, PostgreSQL 16, Docker Compose. Подготовлено 15.10.2026.

**Статус: комплект развёртывания на GitHub. Публичный сервер и домен пока не подключены. GitHub Pages не исполняет PHP и не является хостингом Moodle.** Проверки установки и прав доступа доступны на вкладке [Actions](https://github.com/STEP3DLab/industrialDesign/actions).

## Что создаётся автоматически

- Русскоязычная СДО с оригинальным логотипом РГСУ и оформлением лаборатории.
- Курс: 5 модулей, вводный раздел, итоговый экзамен и скрытый раздел преподавателя.
- Расписание 19.10–04.11.2026: 35 строк, 30 календарных занятий, московское время. Сохранены часы и подписи актуального источника.
- Полный конспект первой лекции; планы остальных материалов скрыты до готовности.
- Самопроверка по первой лекции: 8 вопросов с автоматической проверкой и пояснениями. Не влияет на итоговую оценку и не заменяет аттестацию.
- 4 задания для передачи практических работ + запись очного экзамена с оценкой преподавателя; журнал оценок и обратная связь.
- Стандартный журнал действий, отметки просмотра/отправки работ, отчёт преподавателя по активности и оценке времени, CSV.
- Отдельный процесс cron; резервное копирование; HTTPS через Caddy после подключения домена.

В сборнике лекций тема L02 по допускам не соответствует подтверждённой теме 1.2 «Гражданские и трудовые правоотношения в сфере охраны здоровья граждан». Она оставлена только в скрытом резерве. Подробности: [course/SOURCE-NOTES.md](course/SOURCE-NOTES.md).

## Запуск на сервере или локально

Нужен Linux с Docker Engine и Docker Compose v2. Практический стартовый ориентир для небольшой группы: 2 CPU, 4 ГБ RAM, 40 ГБ SSD; объём диска зависит от файлов сканирования. Покупка ресурсов и изменение DNS автоматически не выполняются.

```bash
git clone https://github.com/STEP3DLab/industrialDesign.git
cd industrialDesign
bash scripts/init.sh
# Отредактируйте .env: адрес СДО и реальную почту администратора.
bash scripts/start.sh
```

Локально: `http://localhost:8080`. Порт привязан только к loopback. Логин администратора — значение `LAB_ADMIN_USER` (по умолчанию `labadmin`). Случайный пароль хранится на сервере в `secrets/admin_password`; его можно прочитать локально владельцу сервера. Пароли в Git не сохраняются.

Портал после входа: `/local/technopark/index.php`. Курс находится в категории «СКБ Технопарка РГСУ». Отчёт времени — пункт «Активность и время» в навигации курса либо кнопка на портале для преподавателя.

Повторный запуск установки не удаляет данные. Повторное наполнение ничего не меняет после успешной первой инициализации. Не удаляйте `seedversion` для обновления курса: редактируйте материалы через Moodle.

## Публичный HTTPS

1. Направьте DNS A/AAAA выбранного поддомена на сервер. Откройте 80/443. PostgreSQL наружу не публикуется.
2. Укажите в `.env`:

```dotenv
MOODLE_URL=https://sdo.your-domain.ru
MOODLE_SSL_PROXY=1
LMS_HOST=sdo.your-domain.ru
LAB_ADMIN_EMAIL=real-address@your-domain.ru
```

3. Запустите `bash scripts/start.sh`, затем:

```bash
docker compose --profile production up -d
```

`your-domain.ru` — пример, а не зарегистрированный или настроенный адрес. Caddy получает TLS-сертификат только после настройки DNS и доступности сервера. Если система уже работала на другом URL, используйте штатную замену URL Moodle после резервной копии.

## Перед началом обучения

- Укажите реальную почту администратора и настройте SMTP в Moodle, проверьте восстановление пароля.
- Создайте/импортируйте пользователей в администрировании; зачислите их в курс. Саморегистрация и гостевой вход отключены. Назначьте роль преподавателя нужным сотрудникам.
- Добавьте ссылки на онлайн-занятия, завершите скрытые конспекты, утвердите тест модуля 1, критерии зачётов и экзаменационные билеты.
- Назначьте условия успешного завершения курса после утверждения программы. Автоматическая выдача документов не включена.
- Для очной и вебинарной посещаемости используйте подтверждённую преподавателем ведомость. Настройки СДО сами по себе не удостоверяют соблюдение всех требований образовательной программы.

## Как считается время

Отчёт читает существующий стандартный журнал Moodle: для каждого действующего слушателя складывает интервалы между соседними веб-событиями в курсе, если интервал не превышает 30 минут. Одиночное событие = 0 минут; конец сессии не дописывается. Отдельно показаны число событий, сессии, выполненные активности и последнее событие.

Это **оценка активности по журналу**, а не таймер внимания, не посещаемость вебинара и не начисление академических часов. Время тестовых попыток доступно в штатном отчёте теста. Плагин не создаёт собственной базы персональных данных. Отчёт закрыт от студентов; CSV требует сессию преподавателя и CSRF-токен. Срок сохранения стандартных логов настроен на 365 дней и может быть изменён администратором.

## Резервное копирование и восстановление

```bash
bash scripts/backup.sh
```

Скрипт включает режим обслуживания, останавливает cron, сохраняет дамп PostgreSQL и весь `moodledata`, затем восстанавливает работу. Каталог `backups/` исключён из Git. Храните защищённую копию вне сервера; секреты резервируйте отдельно.

Восстановление выполняется **на новом пустом экземпляре** той же версии: остановить web/cron, восстановить `database.dump` командой `pg_restore` в пустую базу, распаковать `moodledata.tar.gz` в том `moodledata`, восстановить владельца `www-data`, вернуть `.env` и секреты. Не выполняйте `docker compose down -v` на рабочем сервере: эта команда удаляет данные.

## Обновления

Фиксация Moodle commit обеспечивает воспроизводимость. Проверяйте исправления безопасности ветки 4.5 и обновляйте SHA в Dockerfile осознанно. После полной резервной копии: пересобрать image, включить maintenance, остановить cron, выполнить `php admin/cli/upgrade.php --non-interactive` от `www-data`, вернуть web/cron. Сначала проверьте новую версию на копии. Мажорные версии Moodle не обновляются автоматически.

## Проверки

Workflow `.github/workflows/moodle-check.yml` собирает контейнер, устанавливает Moodle в пустую БД, дважды запускает наполнение (проверка повторного запуска), проверяет курс, календарь, тест, задания и права ролей, затем проверяет вход и ограничения через HTTP. База и тестовые пользователи существуют только в одноразовой среде CI.
